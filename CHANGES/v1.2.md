# TechAmethyst v1.2 (experimental)

`uname -r`: `6.1.138-android14-11-gf7e46d774ebc-TechAmethyst-v1.2`

## What changed vs v1.1
- **Base:** android14-6.1-2025-06_r15 → **android14-6.1-2025-06_r17** (still Linux 6.1.138, KMI generation 11).
  r17 = r15 + 8 upstream/Android fixes:
  - HID logitech-dj / logitech-hidpp: OOB write + use-after-free fixes (4 commits)
  - af_unix: initialise scc_index in unix_add_edge()
  - 16K page-size vma padding robustness (mm/pgsize_migration)
  - arm64/KVM: disable MTE at EL1/EL0 and for guests when unsupported (2 commits)
- **Features:** identical to v1.1: KSU=1 SUSFS=1 BBR=1 NTFS3=1 WLBLOCK=1 TUNE=1 STATUS=1.
  The v1.1 commit was cherry-picked onto r17 with no conflicts and no fuzz; the patch content is byte-identical.
  Note on v1.1 itself: when susfs was first applied to r15, one hunk (`fs/exec.c` #1, the `susfs_def.h` include)
  applied **with fuzz 2**; all other hunks were exact or offset-only. The result was checked: the include is
  placed correctly, so v1.1 and v1.2 are unaffected.
  KernelSU-Next v3.4.1 (33345, pershoot dev-susfs @ 956ea0f5), SUSFS v2.3.0 (susfs4ksu gki-android14-6.1 @ e0b6100).
- **Version:** `-TechAmethyst-v1.2`; `/sys/kernel/techamethyst/version` = `TechAmethyst v1.2`.
- Same toolchain (clang r487747c), same Kleaf target (`//common:kernel_aarch64_dist`).

Git (`~/techamethyst/common`, branch `ta-v1.2`; v1.1 stays on branch `techamethyst` @ ef638e794666):
- `59bf2e18d50a` TechAmethyst v1.1 features on android14-6.1-2025-06_r17
- `f7e46d774ebc` TechAmethyst v1.2: version string -TechAmethyst-v1.2, status node v1.2

## What was verified
- **v1.1 reproduces:** a rebuild of v1.1 unchanged gave a byte-identical Image and boot.img.
  This was a Bazel cache hit; the two v1.2 commits below were real compiles.
- **Config:** the `.config` is identical to v1.1 (0 diff lines).
  MGLRU on (`LRU_GEN_ENABLED=y`), zram default `lzo-rle`, BBR default, NTFS3, KSU, SUSFS all on.
- **ABI check after each commit:**
  - `vmlinux.symvers`: 8142 exported symbols, **0 changed CRC, 0 missing**, vs both v1.1 and the stock r15 baseline.
  - STG: `stg` extracted from vmlinux (filtered to the KMI symbol list) and `stgdiff` against v1.1 gave **no differences**. The KMI symbol list is identical.
  - Google's reference `android/abi_gki_aarch64.stg` is identical between r15 and r17.
- **boot.img:** packed from `techamethyst_v1.1_boot.img`, with only the kernel swapped.
  - Header v4, empty ramdisk, empty cmdline.
  - The AVB hash footer uses the same partition size (100663296) and the same 4 props as stock and v1.1.
  - The kernel inside the image was verified byte-equal to the built Image.
- **AnyKernel3 zip:** same files and script as the v1.1 zip, with only the version text changed.

## Risk
- **Low.** Same sublevel, same KMI, same config and same features; the only kernel code change is 8 small upstream fixes.
  The MTE changes touch arm64 early boot (`head.S`), and they are the most "boot-path" part of this update.
- **Not tested on the device yet.** Use `fastboot boot` first.
- Keep a backup of your **stock** boot.img (dd from the phone) and of the v1.1 boot.img as rollbacks.

## Test plan
1. `fastboot boot boot.img`. Do NOT flash yet.
2. On the phone:
   - `uname -r` should end in `-TechAmethyst-v1.2`, and `cat /sys/kernel/techamethyst/version` should show `TechAmethyst v1.2`.
   - Root still works (KernelSU-Next manager).
   - Wi-Fi, touch, display, sound, camera and modem all work (the vendor modules loaded).
   - `su -c 'dmesg | grep -iE "disagrees about version|Unknown symbol|module verification failed"'` should be empty.
   - `cat /sys/kernel/mm/lru_gen/enabled` should be `0x0003` (core + mm walk; arm64 has no non-leaf PMD young bit, so `0x0007` is not expected); `cat /sys/block/zram0/comp_algorithm` should show `[lzo-rle]`.
3. Only if all of that is fine: flash (`fastboot flash boot boot.img`).
   Rollback: `fastboot flash boot <your v1.1 or stock boot.img>`.
