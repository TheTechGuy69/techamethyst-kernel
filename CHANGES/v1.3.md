# TechAmethyst v1.3 (experimental)

`uname -r`: `6.1.172-android14-11-g0dafe06fba95-TechAmethyst-v1.3`

Files:
- `boot.img`: the kernel (boot partition).
- `system_dlkm.img`: matching GKI modules (zram, zsmalloc, bluetooth, ...), goes into the `system_dlkm` partition in super (via a ROM build).
- `TechAmethyst-v1.3-amethyst-*.zip`: AnyKernel3, **boot only**.

## What changed vs v1.2
- **Base:** android14-6.1-2025-06_r17 (6.1.138) → **android14-6.1-2026-06_r14 (6.1.172)**.
  - KMI generation is still 11. That's 6,908 commits: 6.1 stable backports plus Android fixes up to 2026-10-14.
  - Every commit from the r15/r17 branch is in r14, matched by patch-id or by an identical code change.
    The only exception is the r17 branch's own "Initialize" root commit; r14 has its own equivalent.
- **Features:** same as v1.2: KSU=1 SUSFS=1 BBR=1 NTFS3=1 WLBLOCK=1 TUNE=1 STATUS=1.
  - The same KernelSU-Next (v3.4.1 / 33345, pershoot dev-susfs @ 956ea0f5) and SUSFS v2.3.0 (susfs4ksu @ e0b6100) build unchanged at 6.1.172.
  - Two conflict fixes, both include/declaration placement only, with no logic change:
    - `fs/namespace.c`: r14 added `#include <trace/hooks/blk.h>`, so the susfs include and SUS_MOUNT extern block now sits after it.
    - `fs/proc/base.c`: r14 includes `<linux/dma-buf.h>` itself, so v1.1's "sublevel <= 141" fake include is no longer needed. The susfs include block is added after it.
- **Version:** `-TechAmethyst-v1.3`; `/sys/kernel/techamethyst/version` = `TechAmethyst v1.3`.
- **GKI config changes that come from Google's r14 defconfig** (not from us):
  - Added: POSIX_MQUEUE, IPC_NS, UDMABUF, SECURITY_SAFESETID, EROFS LZMA, ARM64_ERRATUM_4118414, PAGE_BLOCK_ORDER=11,
    and GKI_DYNAMIC_TASK_STRUCT_SIZE (vendor area max 1024).
  - Removed: MEMFD_ASHMEM_SHIM. Google reverted it as "only needed on 6.12+". `CONFIG_ASHMEM=y` stays.
- Same toolchain (clang r487747c) and the same Kleaf target.

Git (`~/techamethyst/common`, branch `ta-v1.3`; v1.2 stays on `ta-v1.2`, v1.1 on `techamethyst`):
- `8d3bbfa5a3b1` TechAmethyst features on android14-6.1-2026-06_r14 (with the two conflict fixes)
- `0dafe06fba95` TechAmethyst v1.3: version string -TechAmethyst-v1.3, status node v1.3

## What was verified
- **Plain r14 baseline** built first. Its config, symvers and KMI list are kept in `~/techamethyst/out/ref-r14/`.
- **Config:** our options on top of r14 are exactly the same set as v1.2's on top of r15.
  MGLRU on, zram default lzo-rle, BBR default, NTFS3, KSU and SUSFS on.
- **CRC (`vmlinux.symvers`):** 8526 exports, **0 changed, 0 missing** vs plain r14. All 8142 exports that v1.2 had are still present with the same CRC.
- **STG:** `stgdiff` vs plain r14 gave **no differences**, and the KMI symbol list is identical.
  - vs v1.2, the only changes are Google's KABI reserved-slot uses (`task_struct`, `mm_struct`, ...) and two enum additions.
  - **0 struct size or offset changes.**
- **`.ko` import gate.** It checked every import's CRC from the module's own `__versions` table, against the stock .ko files from the HyperOS 3.0.306 images:

  | set | modules | imports | CRC mismatch | missing |
  |---|---|---|---|---|
  | vendor_boot ramdisk (stock) | 344 | 16,858 | 0 | 0 |
  | vendor_dlkm (stock) | 311 | 18,493 | 0 | 0 |
  | system_dlkm (new, from this build) | 60 | 3,595 | 0 | 0 |
  | system_dlkm (**stock**, vs the v1.3 kernel) | 60 | 3,591 | 0 | 0 |

  The gate was calibrated on v1.2 (known to boot) first, with the same result.
  The stock system_dlkm also passes, which is why stage 1 below can run v1.3 boot.img on the current ROM.
- **task_struct / WALT:** no stock module uses the new dynamic vendor area (`vendor_data_pad`).
  `sched-walt`, `mi_schedule`, `millet_*` etc. use the fixed `android_vendor_data1[]`, whose offset is unchanged (STG).
- **system_dlkm.img:**
  - Same 60 modules as stock, in both `lib/modules/<release>/` and `flatten/`, with the same `modules.load` order. `etc/` (build.prop, fs_config) is copied from stock.
  - EROFS lz4hc, with the stock UUID and features, a fixed 2009 timestamp, root-owned files and the SELinux label `u:object_r:system_dlkm_file:s0`. fsck OK.
  - The AVB hashtree footer (FEC 2 roots, unsigned) uses the same settings and props as stock.
  - The recipe was checked by repacking the stock image: identical files, modes and owners.
  - The image is 14,950,400 bytes, 16 KB more than stock, so super needs that much free space.
- **boot.img:** packed from `techamethyst_v1.1_boot.img` exactly as in v1.2.
  - Header v4, empty ramdisk, and the stock AVB props and partition size.
  - The kernel inside was verified byte-equal to the build.
- **Zip:** the same AnyKernel3 recipe as v1.2. The kernel string says "boot only - pair with v1.3 system_dlkm".

## Risk
- **Medium.** This is a 34-sublevel jump (6,908 commits), although the KMI is unchanged and the import gate is clean.
  - The most likely trouble spots are vendor module behaviour on new core code (scheduler hooks, mm, binder) rather than load failures.
  - The new dynamic task_struct option is unused by stock modules but new.
- `/dev/ashmem` stays. Only the memfd ashmem-ioctl shim is gone; it was only used if userspace switched ashmem to memfd. Check below.
- system_dlkm's hashtree digest changes. **This needs dm-verity disabled in vbmeta** (as on custom ROMs that repack system/product); on a verified stock vbmeta a changed system_dlkm will not mount.

## Test plan
Record the numbers on **v1.2 first** (current kernel), so you have something to compare against:
`su -c 'lsmod | wc -l'`, `getprop sys.use_memfd`, `ls /dev/ashmem*`

### Stage 1: v1.3 boot.img alone, on the CURRENT ROM (stock 6.1.138 system_dlkm)
1. `fastboot boot boot.img`. Do NOT flash.
2. Checks:
   - `uname -r` ends in `-TechAmethyst-v1.3`, and `cat /sys/kernel/techamethyst/version` shows `TechAmethyst v1.3`.
   - KernelSU-Next manager shows root.
   - `su -c 'dmesg | grep -ciE "disagrees about version|Unknown symbol|module verification failed"'` prints **0**.
   - `su -c 'lsmod | wc -l'` is about the same as on v1.2.
   - `ls /dev/ashmem*` still lists ashmem.
   - `getprop sys.use_memfd` is the same as on v1.2. If it says `true`, watch older apps for crashes, because the shim is gone.
   - WALT:
     - `su -c 'lsmod | grep -i walt'` lists `sched_walt`.
     - `su -c 'ls /proc/sys/walt | head'` is not empty.
     - `su -c 'dmesg | grep -iE "walt|vendor_data" | grep -iE "fail|error|bug|warn"'` is empty.
   - zram: `cat /sys/block/zram0/comp_algorithm` shows `[lzo-rle]`; `cat /sys/kernel/mm/lru_gen/enabled` shows `0x0003`.
   - Wi-Fi, data, touch, fingerprint, charging, camera and audio all work.
3. If anything fails: reboot. Nothing was written.

### Stage 2: ROM build with the new system_dlkm.img in super
1. Build a super image whose `system_dlkm` partition is this `system_dlkm.img` (instead of the stock `system_dlkm_a.img`). Keep the stock one as a backup.
2. Flash that super, then `fastboot boot boot.img` (v1.3) and repeat all of stage 1's checks.
   Also check `su -c 'modinfo -F vermagic /system_dlkm/lib/modules/*/kernel/drivers/block/zram/zram.ko'` shows 6.1.172.
3. Flash boot only if all of that passes.

Rollback:
- Kernel: the v1.2 release `boot.img` (or v1.1 / your stock boot.img).
- ROM: your previous super image.
- **Don't run the v1.2 kernel on the new system_dlkm for long.** The new `usbserial`, `cdc-acm` and `rfcomm` modules import
  `__tty_port_tty_hangup`, which only the v1.3 kernel exports. On v1.2 those three fail to load, along with USB-serial drivers
  like `ftdi_sio` that depend on `usbserial`, and dmesg shows "Unknown symbol".
  Everything else (zram, zsmalloc, bluetooth, ...) passes the gate against v1.2.
  If you roll the kernel back to v1.2, roll super back to the previous rc too.
